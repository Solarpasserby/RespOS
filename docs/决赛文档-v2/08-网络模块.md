# 8. 网络模块

> 本章回答：网络协议栈如何架构？socket 生命周期如何？TCP/UDP 如何实现？

## 8.1 概述

RespOS 的网络模块基于 smoltcp 协议栈构建，提供 TCP/UDP 套接字通信，支持 IPv4/IPv6 协议、loopback 回环设备和 virtio-net 网卡驱动。网络模块的分层架构为：设备层（virtio-net、loopback）→ 网络层（IPv4/IPv6 路由）→ 传输层（TCP/UDP socket）→ 系统调用接口。

## 8.2 设备层

**virtio-net** 设备通过 virtio 框架进行初始化——协商 virtqueue 数量、配置 MAC 地址、建立发送队列和接收队列。数据收发通过 virtqueue 的 descriptor table 进行：发送时将数据包填入 descriptor 并通知设备，接收时从 used ring 取出设备已处理完成的 buffer。

**loopback** 回环设备是一个纯软件设备——发送到 loopback 的数据包直接放回接收队列，无需经过物理网络。loopback 支持标准的 127.0.0.1 IPv4 地址和 ::1 IPv6 地址。

设备层的 poll 机制在每次 `NetDevice::poll()` 调用时处理已到达的接收数据并注入 smoltcp 协议栈，同时尝试发送积压的发送数据。

> 【建议检查的代码】`os/src/drivers/virtio/`，`os/src/net/loopback.rs`

## 8.3 传输层——TCP 与 UDP

RespOS 的 socket 通过 `SocketFile` 结构嵌入 VFS——`SocketFile` 实现 `FileOp` trait，使得 `read/write/poll` 等系统调用能像操作文件一样操作 socket。

**TCP socket 生命周期**：
```
socket() → bind() → listen() → accept() → read/write → close()
                connect() → read/write → close()
```

**listen/accept 模型**。`listen()` 创建监听表条目（`ListenTable`），指定 backlog 深度。`accept()` 从已完成三次握手的 accept queue 取出连接，创建新的 `SocketFile` 返回给用户态。backlog 限制的是尚未被 accept 的连接数——当队列满时新的 SYN 被静默丢弃，符合 TCP 标准行为。

**UDP socket** 是无连接的——`bind()` 绑定本地端口后直接 `sendto/recvfrom`。UDP 的端口管理通过 `PortManager` 实现分配与复用检查。

**端口管理**。`PortManager` 维护全局端口分配表，`bind()` 时检查端口是否可用。支持 `SO_REUSEADDR` 选项允许端口复用。

> 【建议检查的代码】`os/src/net/socket.rs`，`os/src/net/tcp.rs`，`os/src/net/udp.rs`，`os/src/net/listen.rs`

> 【建议准备的图】socket 生命周期；listen backlog → accept queue → accept 时序

## 8.4 网络系统调用

| 系统调用 | 对应实现 |
|---------|---------|
| socket / bind / listen / accept / connect | `syscall/net.rs`，创建/配置 socket |
| send / recv / sendto / recvfrom | 通过 `SocketFile::write/read` → smoltcp socket |
| getsockname / getpeername | 查询本地/对端地址 |
| setsockopt / getsockopt | 配置 SO_REUSEADDR、TCP_NODELAY 等选项 |
| poll / epoll | socket 的 `read_ready/write_ready` + `register_poll_waiter` |

> 【建议检查的代码】`os/src/syscall/net.rs`

## 8.5 当前边界

网络模块当前基于 smoltcp 协议栈，TCP 的重传、拥塞控制和窗口管理等复杂语义由 smoltcp 内部实现。本队的贡献主要在设备驱动适配（virtio-net、loopback）、socket 与 VFS 的集成、以及网络系统调用接口的实现。当前不支持 select 系统调用（仅支持 poll/epoll），IPv6 路由功能有限，真实的以太网帧收发仅限 QEMU 环境，物理网卡驱动仍在开发中。
