# 15. 总结、当前限制与未来工作

## 16.1 本队最终贡献摘要

【本节目的】用可核验证据收束本队贡献，而不是重复所有技术细节。

【建议写什么】从第 2、10、11 章提炼 3–6 条贡献；每条绑定代码、commit、测试状态和架构范围。

【建议检查的 RespOS 代码】第 2 章增量总表中列出的关键路径；最终 `git diff`。

【建议查看的 Git 历史】最终基线与贡献起点之间的 commit；不要统计未经确认的队友/AI贡献。

【建议准备的图 / 表】贡献—代码—证据—状态摘要表。

【建议准备的测试 / 数据】每条贡献的最小复现命令和最终日志。

【容易出现的问题】不要用代码行数、模块数量或历史分数替代功能证据。

## 16.2 当前限制与未完成项

【本节目的】诚实列出最终版本尚未完成、仅部分验证或受环境限制的内容。

【建议写什么】至少审查：完整 BuildStorm minibuild/compile、LA64 SMP、signal 全覆盖、COW/mprotect 压力、pipe/fd 生命周期、`MS_INVALIDATE`/SIGBUS 等实际边界；逐项标状态。

【建议检查的 RespOS 代码】`docs/codex/current-status.md`、`pitfalls.md`；最终源码和最终日志。

【建议查看的 Git 历史】最终 commit；确认未把未提交实验写成最终能力。

【建议准备的图 / 表】已验证/部分验证/未实现/待验证四分类表。

【建议准备的测试 / 数据】为每个限制写当前最后一次尝试的命令、日志和失败位置；保留失败样本。

【容易出现的问题】限制不是道歉段落，而是结果可解释性的一部分；不能用“理论上支持”填入已验证列。

## 16.3 复现入口与未来工作

【本节目的】给评审和后续维护者一个从干净工作树复现、继续推进的入口。

【建议写什么】链接 README/第 10 章命令、镜像恢复方式、优先修复顺序和未来架构/性能方向；区分已计划与已承诺。

【建议检查的 RespOS 代码】`README.md`；`Makefile`；`docs/codex/workflows.md`；`buildstorm-smp-plan.md`。

【建议查看的 Git 历史】最终 commit 和当前分支；未来工作不得伪装成当前成果。

【建议准备的图 / 表】复现路径图；限制→下一实验→成功标准表。

【建议准备的测试 / 数据】最小 smoke、专项 probe、完整比赛回归和性能基线命令。

【容易出现的问题】不要承诺没有资源/测试计划支撑的功能；未来方向要与当前限制一一对应。
