# RespOS 决赛设计文档大纲

> 本目录是写作骨架，不是正式设计文档正文。方括号内容需要团队根据最终提交版本、最终测试日志和比赛要求补齐；未核验内容必须标为“待验证”。

## 0.1 本大纲的证据边界

- 代码基线：当前工作树 `b785262`（2026-08-07，`dev`）；提交前应重新记录最终 commit。
- 版本关系：外部基础版本 → 初赛版本 → 决赛最终版本。不能用 README 中历史成绩替代当前结果。
- 证据优先级：当前源码/构建脚本/运行日志 > 可定位的 Git 历史 > 旧文档与 README > 模型记忆。
- 状态标记：`已确认`、`待验证`、`历史记录`、`最终版待补`。
- 正式文档只填写本目录预留的位置；诊断 trace、临时 probe、未完成 BuildStorm 结果不能直接当作最终功能。

## 0.5 全文统一写作模板

每个技术小节至少保留以下七项：

1. **【本节目的】**：本节要回答的一个问题。
2. **【建议写什么】**：围绕背景、原有状态、最终方案、生命周期、并发与取舍填写，避免 API 罗列。
3. **【建议检查的 RespOS 代码】**：精确到目录、文件和关键函数/类型。
4. **【建议查看的 Git 历史】**：commit、`git show` 目标和需要确认的版本差异。
5. **【建议准备的图 / 表】**：只准备能解释调用链、所有权、状态或版本差异的图表。
6. **【建议准备的测试 / 数据】**：命令、环境、重复次数、日志和 pass/fail 规则。
7. **【容易出现的问题】**：与当前已知边界、历史成绩过期、镜像污染和未验证结论相关的提醒。
