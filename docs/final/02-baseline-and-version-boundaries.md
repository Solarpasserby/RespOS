# 2. 基础版本、初赛版本与版本边界

> 本章只负责建立版本基线和材料索引。决赛实现的具体变化放回对应技术章节，待实现优化完成后再填写；这里不提前写决赛方案或成绩。

## 2.1 三个版本的定义

【本节目的】明确外部基础版本、初赛版本和决赛最终版本各自的 commit、镜像和边界。

【建议写什么】分别填写基础项目名称/版本（未知则待确认）、初赛提交 commit、决赛最终 commit；说明哪些分支/标签仅为历史参考。

【建议检查的 RespOS 代码】`README.md`；`.git/` refs；`docs/初赛文档/`；`Makefile`；镜像文件与脚本。

【建议查看的 Git 历史】`git log --all --decorate`；`main`、`docs/pre`、`contest-images-2026`、`dev`；核对 `3839e4e` 到当前 `b785262`。

【建议准备的图 / 表】三版本时间线；版本卡片（commit、日期、架构、镜像、可复现命令）。

【建议准备的测试 / 数据】每个版本至少一条构建/运行记录；历史分数须带来源、日期、命令和环境。

【容易出现的问题】当前 `docs/codex/current-status.md` 含有旧基线描述，不能不经核对直接复制；外部基础版本的身份若无法从历史证明，必须标“待人工确认”。

## 2.2 版本差异材料索引

【本节目的】为各技术章节提供版本差异的取证入口，不在本章单独展开“决赛增量”或提前评价最终实现。

【建议写什么】按任务、调度、MM、FS/ABI、网络、双架构、测试基础设施等模块登记：基础/初赛/当前工作树的代码位置、相关 commit、待优化问题和应回填的技术章节；最终方案由各章节负责人完成后再补。

【建议检查的 RespOS 代码】`os/src/task/`、`mm/`、`fs/`、`net/`、`arch/`、`syscall/`、`user/`；`docs/四天内核重构-ABC-整合审查.md`。

【建议查看的 Git 历史】`15fe1a5`、`3aa1fb5`、`cba8e24`、`dc793c4`、`17dcd4e`、`f326ac8`、`b785262`；仅用于建立材料索引，不直接替代最终实现说明。

【建议准备的图 / 表】材料索引表：模块｜基础/初赛代码｜当前代码｜关键 commit｜待优化问题｜正文归属章节｜验证状态。原“基础版本已有—初赛完成—决赛新增/重构”总表不再作为独立成章内容。

【建议准备的测试 / 数据】每一行至少绑定一个代码路径和一个测试/日志；未完成工作只登记证据和下一步优化目标，不放进已完成列。

【容易出现的问题】不要把依赖库原有能力算成本队贡献；不要按文件增删行数代替功能增量；同一修复最终只在所属技术章节展开一次。

## 2.3 初赛材料与技术章节的映射

【本节目的】解释初赛文档已经覆盖的内容，并把需要后续优化的决赛材料分配回对应章节，避免新增一个独立的决赛工作章。

【建议写什么】从初赛 PDF/Typst 提取已有基线；将 ABI 收敛放入 `07/08`，任务与并发放入 `04/05/11`，MM/ELF 放入 `06`，双架构/SMP 放入 `09`，比赛验证放入 `10`，版本过程放入 `12`。暂时只建立材料映射，不写优化后的最终实现。

【建议检查的 RespOS 代码】`docs/初赛文档/main.typ` 及其 figures；当前对应 `os/src/` 模块；`docs/dev-log.md`。

【建议查看的 Git 历史】`git show docs/pre:docs/初赛文档/main.typ`；`5737bd2`、`da2f977`；对照 `main...dev` diff。

【建议准备的图 / 表】“初赛设计图复用/更新/废弃”表；材料→技术章节映射表；不再单独绘制“决赛增量”总览图。

【建议准备的测试 / 数据】初赛最后版本与最终版本同一命令的可比结果；如果环境不同，显式标不可直接比较。

【容易出现的问题】初赛文档中的设计意图不一定等于当前代码；旧图中的队列、时钟、SMP 状态可能已过时；当前决赛实现也不能在优化前冻结为正式结论。
