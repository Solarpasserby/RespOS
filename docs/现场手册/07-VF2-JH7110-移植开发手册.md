# VF2（JH7110）移植开发手册 —— 保姆级

> 本文档是 VisionFive 2 真机移植的**完整开发过程记录 + 操作手册**，面向「明天现场赛、不能联网、需要知道改干什么」的场景。
> 一切以**当前仓库源码 + 可复现命令**为准；遇到不一致先跑 `git rev-parse --short HEAD` 记下提交。

## 0. 仓库现状（先看这一节）

- 当前分支是 **`main`**，之前的 `port/jh7110` 已经合并进来。
- 内核现在是「**板级可插拔**」架构：板级策略集中在 **`os/src/platform/`**，由 Cargo feature 编译期选择。

| feature | 架构 | 板子 | 平台文件 |
|---|---|---|---|
| （无，默认） | riscv64 | QEMU virt | `os/src/platform/qemu_rv64.rs` |
| `board_jh7110` | riscv64 | **VisionFive 2** | `os/src/platform/jh7110.rs` |
| （无） | loongarch64 | QEMU | `os/src/platform/qemu_loongarch64.rs` |
| `board_ls2k1000` | loongarch64 | 2K1000 龙芯板 | `os/src/platform/ls2k1000.rs` |

`board_jh7110` 与 `board_ls2k1000` **互斥**（`os/src/platform/mod.rs` 里有 `compile_error!` 校验）。

## 1. 构建（最重要，先背下来）

VF2 内核构建（产出 `kernel-vf2.bin`）：

```bash
CMAKE_POLICY_VERSION_MINIMUM=3.5 RUSTUP_TOOLCHAIN=nightly-2025-01-18 make build-vf2
```

- **必须带这两个环境变量**：`CMAKE_POLICY_VERSION_MINIMUM=3.5` 是为了绕过 vendored lwext4 的 `cmake_minimum_required(VERSION 3.4)` 与宿主 CMake 4.x 的冲突；`RUSTUP_TOOLCHAIN=nightly-2025-01-18` 锁定工具链。
- 产出：`kernel-vf2.bin`（raw binary，带 RISC-V Image 头，装载地址 `0x40200000`）。
- 内部做的事（`make build-jh7110`）：`prepare-jh7110-cargo-config`（拷贝 `os/cargo/config-jh7110.toml`）→ 构建 riscv64 用户程序 → `cargo build --features "board_jh7110 ..."` → `rust-objcopy -O binary --gap-fill=0`。

QEMU RV64 基线回归（**改动后必须跑，确保没破坏 QEMU**）：

```bash
CMAKE_POLICY_VERSION_MINIMUM=3.5 RUSTUP_TOOLCHAIN=nightly-2025-01-18 make build-rv
```

产出 `kernel-rv`。

其它常用：`make build-la`（QEMU LoongArch）、`make build-la-ls2k1000`（2K1000）。`make help` 看全部 target。

## 2. SD 卡刷机 / 部署（一次性做完后，日常只需换内核）

当前 SD 卡已经是**分区好的自举卡**，布局：

| 分区 | 类型 | 起始扇区 | 内容 |
|---|---|---|---|
| p1 | FAT32 | 2048 | `kernel-vf2.bin` + `boot.scr`（引导） |
| p2 | ext4 | **526336** | alpine 根文件系统 |

`526336` 这个数在 **`os/src/platform/jh7110.rs` 的 `ROOT_DISK_BASE_BLOCK`** 里，内核据此把根盘偏移到 p2。

### 2.1 首次分区（只在「卡是整卡 ext4、没分区」时做）

```bash
# 确认设备（fish 环境，用 printf 管道代替 heredoc）
lsblk   # 确认 SD 卡是 /dev/sda

printf 'label: dos\nstart=2048, size=524288, type=c, bootable\nstart=526336, type=83\n' | sudo sfdisk --wipe always /dev/sda
sudo partprobe /dev/sda
sudo mkfs.vfat -F 32 -n BOOT /dev/sda1
sudo dd if=img/alpine-linux-riscv64-ext4fs.img of=/dev/sda2 bs=4M oflag=direct status=progress
sync
```

> **fish 用户注意**：fish 不支持 `<<'EOF'` heredoc，用 `printf '...\n' |` 管道（如上）。

### 2.2 每次换内核（日常操作，只换 p1 的 kernel-vf2.bin）

```bash
sudo mount /dev/sda1 /mnt
sudo cp kernel-vf2.bin /mnt/
sudo umount /mnt
```

p2 的 ext4 根分区**完全不用动**。

### 2.3 首次放 boot.scr（引导脚本，只需做一次）

```bash
printf 'fatload mmc 1:1 0x40200000 kernel-vf2.bin\nbooti 0x40200000 - ${fdtcontroladdr}\n' > /tmp/boot.scr
sudo mount /dev/sda1 /mnt
sudo cp /tmp/boot.scr /mnt/
sudo umount /mnt
```

> `boot.scr` 是 raw 文本脚本，U-Boot 的 `distro_bootcmd` 会 `source` 它。但本板默认 `boot_targets=mmc0 dhcp` **漏了 mmc1**，所以实际用的是下面 3.1 的 `saveenv` 覆盖。

## 3. 启动（U-Boot 一次性配置）

### 3.1 覆盖 bootcmd（让上电自动从 SD 启动，只需做一次）

上电时按任意键停住 autoboot，在 U-Boot 里敲（**注意单引号**，保护 `;` 和 `${fdtcontroladdr}`）：

```
setenv bootcmd 'fatload mmc 1:1 0x40200000 kernel-vf2.bin; booti 0x40200000 - ${fdtcontroladdr}'
saveenv
printenv bootcmd    # 应原样显示那一串，${fdtcontroladdr} 没被提前展开
```

之后每次上电，U-Boot 自动 `fatload` → `booti`，**不需要 TFTP、不需要手敲任何命令**。

### 3.2 为什么是覆盖而不是 distro 引导

本板 SD 卡枚举成 **`mmc 1`**（不是 mmc0），而 `boot_targets=mmc0 dhcp`，所以标准 `distro_bootcmd` 扫不到 SD。两种修法：

- 方案 A（已用）：`saveenv` 直接覆盖 `bootcmd`（最确定）。
- 方案 B（备选）：`setenv boot_targets 'mmc1 dhcp'; saveenv`（保留 distro 流程，但依赖 `bootcmd_mmc1` 定义正确）。

## 4. 冒烟测试（软件兼容性验证）

现在 `contest_launcher` 在 **software 模式**下会自动把内嵌的冒烟脚本写到 **`/tmp/software-smoke.sh`**（不自动运行）。进 Alpine shell 后手动跑：

```sh
sh /tmp/software-smoke.sh
```

脚本内容（`auxfs/payloads/software/software-smoke.sh`，编译期内嵌进 contest_launcher）：

| 项 | 测什么 |
|---|---|
| `git_local` | git `init/config/add/commit/status/log` 本地仓库全流程 |
| `vim_batch` | vim `-Nu NONE -n -es` 批处理替换 |

## 6. 踩坑清单（保姆级，逐个有解）

### 6.1 构建
- **CMake 报 `Compatibility with CMake < 3.5 has been removed`** → 必须带 `CMAKE_POLICY_VERSION_MINIMUM=3.5`。
- **lwext4 重编译失败** → 确认用了 `RUSTUP_TOOLCHAIN=nightly-2025-01-18`，且先 `make build-vf2`（会先跑 lwext4 的 build script）。

### 6.2 启动
- **`Bad Linux RISCV Image magic!`** → 99% 是 TFTP/加载没传完，0x40200000 是垃圾；不是内核问题。先查网络/文件。
- **TFTP `ARP Retry count exceeded`** → 宿主机有线网卡 IP 丢了。修：
  ```bash
  sudo ip addr add 192.168.1.100/24 dev enp129s0   # 或 nmcli 建静态连接
  ```
- **`Card did not respond to voltage select! : -110`**（U-Boot 早期）→ **瞬时噪声，无害**，后面 `fatload` 能读到卡就没事。别被它吓到。
- **`** No partition table - mmc 1 **` / `Couldn't find partition mmc 1:3`** → 卡没分区（整卡 ext4）或 bootcmd 还在用旧流程。做 2.1 分区 + 3.1 saveenv。

### 6.3 文件系统
- **宿主 `mount /dev/sda2` 报「结构需要清理」（EUCLEAN）** → 板子读写挂载后直接断电，脏 journal。先：
  ```bash
  sudo fsck.ext4 -f -y /dev/sda2
  ```
  再 mount。**拔卡前在 shell 里 `poweroff`/`reboot` 干净关机**可减少发生。
- **内核 panic `failed to initialize root EXT4 filesystem: EINVAL`** → 实际错误被 `super_block.rs` 映射成了 EINVAL。常见两个原因：
  1. `ROOT_DISK_BASE_BLOCK` 与分区不对（偏移错，读不到超级块）；
  2. SD 时钟档位不稳（数据读错）。看串口里 `clock_div=X` 是否正常。

### 6.4 SD 性能（当前已知瓶颈）
- **`div=4/8` superblock checksum 失败、`div=16` 才稳**：高时钟下「第二个连续块」读取出错（`read_single` 的 DTO/FIFO 时序竞态，div=63 慢时钟下修过、高时钟复发）。这是**下一个要修的性能 bug**。
- 修好后可回 `div=8`（~12MHz）甚至 `div=4`（~25MHz），再做 4-bit 总线（ACMD6 + CTYPE）可再快 ~4 倍，逼近 U-Boot 的 21.6 MiB/s。

### 6.5 其它
- **fish heredoc** → 用 `printf '...\n' |` 管道，别用 `<<'EOF'`。
- **`printenv`/`saveenv`** → U-Boot 里 `saveenv` 写 SPI Flash，已确认可用。

## 7. 待办（明天之后可选的推进方向）

1. **SD 性能攻坚（最推荐，收益直接）**：修「高时钟下连续读竞态」→ 回 `div=8/4` → 做 4-bit 总线。
2. **Stage 6 网络（GMAC）**：`os/src/drivers/` 新增 stmmac 驱动 + PHY，替换 virtio-net。工程量大（DMA 描述符环 + MDIO + 时钟复位），可复用 U-Boot 已配好的 PHY/时钟状态。
3. **Stage 7 SMP**：4×U74 核上线，关键坑 hart0=S7 无 MMU、hart id 1..4 映射。
4. **RTC 墙钟**：JH7110 AON 域 RTC 驱动，让 `date`/`git commit` 时间戳正确。
5. **PMIC 电源管理**：`quit` 后那串 `i2c read` 报错（OpenSBI PMIC 关机失败），已在 VF2 下把 poweroff 改成冷重启规避。
