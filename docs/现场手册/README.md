# RespOS 现场故障处理手册

这套手册用于比赛现场快速定位 RespOS 故障，不替代操作系统教材，也不替代
[`docs/codex/`](../codex/) 中带证据的完整工程记录。遇到不一致时，以当前源码、构建脚本、当前提交的
可复现日志和官方现场通知为准。

本文档按仓库 `4e774604f36f`（2026-08-18）整理。以后使用时先执行 `git rev-parse --short HEAD`；若
提交已变化，把这里当作入口索引，而不是当前测试结论。

## 现场先看这一页

1. 记录 `HEAD`、架构、平台、镜像校验值、完整命令和首个异常；不要先改代码。
2. 判断失败属于启动、用户异常、卡死、文件系统、网络还是测试框架。
3. RISC-V 与 LoongArch 做 A/B 对照；只坏一个架构时先查 `os/src/arch/` 和平台配置。
4. 从首个真实失败向前查，后续大量 `TBROK`、超时或僵尸任务可能只是级联。
5. 最小化复现，一次只改变一个变量；记录每次结果。
6. 修复后至少做目标架构专项测试、双架构构建、`git diff --check` 和 `git status --short`。
7. 准备提测时使用 `make preflight`；只有已提交且工作区干净时才使用 `make package-submit`。

## 十分钟开场检查

```bash
git status --short
git rev-parse --short HEAD
git log -5 --oneline --decorate
rustc --version
cargo --version
qemu-system-riscv64 --version | head -n 1
qemu-system-loongarch64 --version | head -n 1
make help
```

再确认镜像和磁盘空间：

```bash
sha256sum img/*.xz img/*.img 2>/dev/null
df -h . /tmp
```

校验值应与本地离线包的清单比较，不能仅凭文件名判断镜像版本。比赛镜像是可变测试状态；正式运行
入口使用快照，但手工 QEMU 命令或其他工具仍可能写盘。

## 赛前必须由官方规则确认

下面各项在本仓库中故意不写“允许”或“禁止”，赛前根据最新正式通知填表并保存来源：

| 项目 | 结论 | 官方依据/日期 |
| --- | --- | --- |
| 是否允许互联网、局域网或远程仓库 | 待确认 | |
| 是否允许 U 盘、移动硬盘及几份备份 | 待确认 | |
| 是否允许纸质材料和本地电子文档 | 待确认 | |
| 是否允许预装工具链、容器、依赖缓存和镜像 | 待确认 | |
| 是否允许现场使用 AI、聊天记录或个人知识库 | 待确认 | |
| 现场机器是否会重置；何时导入资料 | 待确认 | |
| 源码、日志和最终产物的提交方式与大小限制 | 待确认 | |

## 建议打印顺序

优先打印本页、故障树、ABI 表、命令速查和一张空白故障记录。长篇历史与规范保留在离线电子资料中。
现场材料的价值是缩短“首个可靠证据”出现的时间，而不是覆盖所有操作系统知识。
